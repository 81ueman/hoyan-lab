Use the code-review skill.

Review this worktree against base `main`. Include both committed branch changes and uncommitted working-tree changes. Use commands such as:

- `git diff main...HEAD`
- `git diff`
- `git status --short`

Spec source: `.pi-task.md` in this worktree. Treat it as the originating spec.

Implementation pane to notify when finished: `wQ:p1`.
Review pane/tab to close after successful relay: `wQ:p2` / `wQ:t2`.

Focus on actionable findings only. Report:
1. Standards findings
2. Spec findings
3. Must-fix items before PR
4. Nice-to-have items
5. Whether this is PR-ready

Do not modify source files except for the review relay files described below.

After producing the review, you are responsible for relaying it to the implementation agent:

1. Write `.pi-review-output.md` with your review result.
2. Write `.pi-fix-request.md` with this format:

   The code-review agent finished. You are the implementation agent for this branch.

   Please triage the review output below:
   - Fix every valid Must-fix item.
   - If a finding is a false positive or intentionally out of scope, explain why.
   - Keep the branch focused on the original `.pi-task.md`.
   - Run relevant tests after any changes.
   - Report:
     - classification of each review finding
     - files changed
     - how each valid finding was addressed
     - test command and result
     - whether the branch is ready for re-review

   Review output:

   <your review result>

3. Send it to the implementation pane:

   `herdr pane run wQ:p1 "@.pi-fix-request.md"`

4. After confirming the relay command succeeded, close your own review tab/pane:

   `herdr tab close wQ:t2`

If there are no findings, still notify the implementation pane and ask it to confirm readiness for PR before closing.
